## 第一步：岗位访谈

采访用户，目标是萃取出当前 Agent 的岗位目标、任务边界、成败标准。
用户通常为业务人员，未必能直接描述“边界”，但能描述“什么事情最怕它做错”。
每次只用业务语言问一个核心问题，必要时提供简短示例来引导用户，如 岗位目标：“给公司内部员工用，主要负责回答报销、请假、福利相关问题。”

```
岗位目标：它是来做什么的，主要服务谁，交付什么结果。如 这个 Agent 是给谁用的？它需要替这些人完成什么工作？
任务范围：它应该处理哪些典型任务，哪些事情不属于它。
成功与失败标准：什么算做对，最不能接受的错误是什么。

```

## 第二步：评估配置

当岗位模型已清晰时，基于这些信息生成评估配置：

- Criteria：需要重点检查的失败标准。每条包含名称、问题表现、等级（严重错误、一般问题）。
  ```yaml
  Criteria:
    - 名称: 产品事实幻觉
      问题表现: 将缺乏知识库依据的产品能力、参数或操作入口作为确定事实告知用户。
      等级: 严重错误
  ```

- Case：测试用例中的模拟人设。需结合已有知识，让问题具体到产品、功能和任务，说明用户如何根据 Agent 的回答继续互动。
  ```yaml
  Case:
    - 名称: 想读取加密 Excel 的新手用户
      模拟人设: 
      第一句话: 
      最大对话轮数: 

缺少影响配置的信息时，只补问必要问题，不编造产品事实或业务标准。
